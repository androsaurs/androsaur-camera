# Локальный прототип

Прототип проверяет CameraX, фоновую службу и сервер на телефоне. Это ещё не
интеграция с paper-ledger и не окончательный выбор сетевой библиотеки.

## Сборка и запуск

Нужны JDK 17, Android SDK 35 и доступ к Maven-репозиториям.

```sh
./gradlew :androidApp:assembleDebug :shared:jvmTest
adb install -r androidApp/build/outputs/apk/debug/androidApp-debug.apk
```

При первичной настройке открыть «Mobile Ledger · прототип» и разрешить камеру
и уведомления. Служба подключения запускается автоматически при открытии
приложения; отдельное нажатие «Запустить камеру» больше не требуется.
Приложение показывает адрес пульта с индивидуальным кодом
доступа в URL fragment. Открыть адрес на компьютере в той же сети. Код пульта
хранится только локально; не публиковать полный адрес с fragment.

В обычной работе запуск съёмки и калибровки выполняется из paper-ledger;
служба телефона остаётся в фоне, камера без клиентов освобождается.
`START_STICKY` позволяет системе запланировать восстановление службы после
выгрузки процесса. Это не гарантия живучести на прошивках Xiaomi и не обход
принудительной остановки, отзыва разрешений или ограничений Android на запуск
camera foreground service после перезагрузки. Если приложение полностью
остановлено и HTTP-сервер не работает, входящая команда Wi-Fi его не разбудит.

Пульт делает низкочастотное JPEG-превью (~2–3 кадра/с); фотография создаётся
отдельным ImageCapture. На каждую команду передаётся один JPEG, без последующей
обработки оригинала. Превью поворачивается отдельно, JPEG использует ориентацию
CameraX/EXIF. Пульт предоставляет скачивание оригинала; последний принятый
`File` доступен как `window.lastCameraFile` для проверки границы адаптера.

Для USB-проверки, независимо от Wi-Fi:

```sh
adb forward tcp:18088 tcp:8088
node scripts/smoke.mjs
```

Для проверки освобождения камеры и повторного открытия добавить `--idle`;
перед этим закрыть пульты, иначе их запросы будут поддерживать камеру активной.

Скрипт сам получает токен установленной debug-сборки через `run-as`, не печатает
его и не сохраняет фотографии. Результаты — `artifacts/device-smoke.json`.
Чтобы проверить LAN, указать `CAMERA_BASE=http://IP-ТЕЛЕФОНА:8088`.

## Интерфейс прототипа

### Калибровка положения телефона

На главном экране кнопка «Калибровка» открывает отдельное живое превью.
Разместите одинаковые QR-коды так, чтобы их центры образовали прямоугольник
на плоской подложке, за пределами документа. Содержимое меток:

| Угол | Точный текст QR |
| --- | --- |
| Верхний левый | `mobile-ledger:calibration:v1:TL` |
| Верхний правый | `mobile-ledger:calibration:v1:TR` |
| Нижний правый | `mobile-ledger:calibration:v1:BR` |
| Нижний левый | `mobile-ledger:calibration:v1:BL` |

Распознавание — встроенная модель ML Kit, без загрузки модели при первом
запуске. Для анализа используются только кадры задней камеры, без датчиков
уровня, размеров подложки и программного выпрямления. Центр QR определяется
пересечением диагоналей его четырёх углов, а не средним координат.

Рамка показывает обнаруженный четырёхугольник. Текстовые команды у краёв превью
указывают, какой край **телефона в текущей ориентации экрана** приподнять.
Калибровка учитывает перспективную составляющую и прямоугольность;
обычный поворот прямоугольника в плоскости кадра не считается наклоном.
Это оценка относительного перекоса, не измерение углов в градусах.
Допуск по умолчанию — 1% для нормированной перспективной
ошибки и косинуса отклонения соседних сторон от прямого угла.
После 1,2 с непрерывного выравнивания рамка становится зелёной.
При потере меток, дублях, неправильной геометрии или устаревшем анализе
готовность сбрасывается. Допуск нужно проверить на напечатанной подложке.

На время калибровки камера принадлежит этому экрану: `/status` сообщает
`calibrating`, новые запросы съёмки получают `503 camera_unavailable`.
Повтор ранее принятого запроса и получение/ACK готового снимка продолжают
работать. Текущая экспозиция не прерывается: экран предлагает повторить вход
после съёмки. Выход освобождает превью и возвращает обычный режим службы;
служба остаётся запущенной, как после кнопки «Запустить камеру».
Фото и результаты калибровки не сохраняются. После фиксации крепления можно
вернуться на главный экран и снимать с компьютера.

Область превью имеет постоянный размер при неизменной ориентации окна.
Для нижней панели выделена фиксированная высота; длинные сообщения доступны
через прокрутку. Переносы текста и появление команд поверх изображения
не меняют размер камеры. Вместо шевронов показаны команды «Приподнимите
правый/левый/верхний/нижний край» у соответствующей стороны экрана.

Допуск меняется во время работы через авторизованный API сервера телефона:
`POST /calibration/tolerance`, JSON `{"tolerancePercent": 1.0}`.
Значение задаётся в процентах, допустимы числа от 0,1 до 5 включительно;
строки, отсутствующее значение и числа вне диапазона возвращают 400
`invalid_calibration_tolerance`. Без Bearer-токена запрос получает 401.
Ответ 200 содержит `{"tolerancePercent": 1.0}`; в `GET /status` текущее
значение доступно как `calibrationTolerancePercent`.

Настройка сохраняется в приватных preferences телефона, применяется к
следующему результату распознавания без перезапуска камеры и не меняет
геометрию превью. При изменении сбрасывается выдержка стабильности 1,2 с.
Тот же порог используется для направления подсказок и готовности; текущий
допуск показан текстом на экране, локального регулятора нет.
Команду может отправить сервер paper-ledger или другой авторизованный
HTTP-клиент при наличии сетевого доступа к телефону. CORS не включается.

Проверка на устройстве: все четыре наклона, поворот экрана, исчезновение
одной метки, дубли QR, возврат назад/фон и возобновление съёмки с компьютера.
Оптическая дисторсия, неровная подложка и неточная печать влияют на оценку.

Все API требуют `Authorization: Bearer <код с телефона>`. Встроенная HTML-страница
доступна без токена, но камера и данные защищены токеном. CORS не включён;
интеграцию публичного HTTP-origin нужно проверить отдельно.

| Запрос | Назначение |
| --- | --- |
| `GET /` | Пульт камеры |
| `GET /status` | Состояние, session, разрешения, подсветка; поддерживает камеру активной |
| `GET /status?passive=1` | То же состояние без включения/удержания камеры |
| `GET /frame.jpg` | Последний JPEG превью (до ≈30 кадров/с, зависит от света); заголовки `X-Frame-Id` (номер кадра, растёт на каждый закодированный кадр) и `X-Frame-Age-Ms` (возраст кадра в телефоне); 202 при прогреве или если кадр старше 2 с. Кадры кодируются только пока их запрашивают (≈3 с после последнего запроса) |
| `POST /capture` | `{requestId, clientId, width?, height?}`; 202 принят, 409 занят/конфликт, 503 недоступен |
| `GET /result?requestId=…&clientId=…` | 202 ожидается, 200 JPEG, 410 отменён/подтверждён/заменён |
| `POST /ack` | `{requestId, clientId}` — браузер получил файл, удалить локальную копию |
| `POST /cancel` | `{requestId, clientId}` — отменить запрос этой вкладки |
| `POST /torch` | `{enabled: boolean}` — постоянная подсветка |
| `POST /calibration/tolerance` | `{tolerancePercent: number}` — допуск калибровки 0,1–5%, сохраняется между запусками |
| `POST /calibration/session` | `{clientId: string, active: boolean}` — аренда удалённой калибровки на 12 секунд |
| `GET /calibration/frame` | JSON: JPEG-превью и геометрия одного кадра; 202 при прогреве, 409 без калибровки |
| `POST /mcp` | MCP (Streamable HTTP, JSON-RPC, без сессий и SSE) для ИИ-агента, см. ниже |

### MCP для ИИ-агента

Сервер MCP встроен в приложение (`McpEndpoint`), без отдельных процессов и
сторонних библиотек. Подключение с тем же кодом доступа, что и у остальных API:

```sh
claude mcp add --transport http mobile-ledger http://IP-ТЕЛЕФОНА:8088/mcp \
  --header "Authorization: Bearer <код с телефона>"
```

Результат инструмента всегда попадает в контекст модели, поэтому фотография
никогда не возвращается inline. Снимок агента — это **хэндл** в отдельном
хранилище; агент выбирает, сколько платить токенами: только метрики, картинка
для собственного анализа или передача оригинала ссылкой без чтения байтов.

| Инструмент | Назначение |
| --- | --- |
| `status` | Состояние, разрешения, подсветка, фокус, использование хранилища (`captureStore.bootId`). Камеру не будит |
| `preview` | Живой кадр ~640×480 как изображение |
| `take_photo` | Снимок в хранилище: `handle`, размер, `sha256`, `focus`, `captureMs`. Метрики только при `include_metrics`, картинка только при `include_preview`. Необязательный `request_id` делает вызов идемпотентным |
| `view_capture` | Уменьшенная картинка снимка по хэндлу, не больше ~1,15 Мп (~1500 токенов), `max_edge` 256–1568 |
| `view_region` | «Лупа»: вырез в родном разрешении без апскейла, `x,y,w,h` — доли 0–1 показываемого (с учётом EXIF) снимка |
| `get_capture_link` | Ссылка `/dl/<токен>` на оригинал для другого сервиса или инструмента, без Bearer |
| `list_captures`, `get_capture_info` | Список хэндлов и полные метаданные |
| `release_capture` | Удалить снимок и его ссылки |
| `torch`, `focus` | Подсветка и фокусировка, как в HTTP-API |

**Метрики считаются только по запросу** (`include_metrics` в `take_photo` или в `get_capture_info`;
без него обработка не запускается ни при съёмке, ни при просмотре списка и информации), около
0,1–0,2 с на снимок; посчитанные один раз сохраняются со снимком, повторный запрос бесплатен.
Считаются они на телефоне по копии 1024 px показываемого снимка:
`sharpness` (дисперсия лапласиана), `sharpnessCenter`, `sharpnessGrid` (4×4,
строки сверху вниз — те же координаты, что у `view_region`), `meanBrightness`,
`contrast` (0–255), `overexposedPercent`. Пустая бумага даёт низкую резкость,
не будучи размытой, поэтому сравнивать нужно одну и ту же область между
повторными снимками. Пороги «годен / переснять» ещё не определены измерениями.

**Хранилище агента** независимо от слота браузера: съёмка со вкладки и ACK не
удаляют снимки агента, а новая съёмка агента не заменяет прежний хэндл. Камера
общая — занятая отвечает `camera_busy` обоим. Снимок удаляется с телефона:
сразу после того, как одноразовая ссылка отдала последний байт; по
`release_capture`; через 1 минуту после последнего обращения (просмотр, ссылка,
`get_capture_info` продлевают срок; живая ссылка держит снимок до своего
истечения). Съёмка никогда не блокируется заполнением: при 24 снимках или
120 МБ вытесняется давно не использованный (снимки с живой ссылкой — в
последнюю очередь), а хэндлы вытесненных приходят в поле `evicted` ответа
`take_photo`. Хэндл имеет вид `<bootId>-<8 hex>`; после перезапуска приложения
файлы удаляются. Ответ `not_found` содержит `reason`: `restarted`, `released`,
`delivered`, `evicted`, `never_existed`; истёкший снимок — ошибка `expired`.

**Ссылки** (`GET /dl/<32 hex>`): токен ссылки случайный и является единственным
правом доступа; по умолчанию живёт 1 минуту (10–3600 с) и одноразовый — гаснет
ответом, доставившим последний байт, и вместе с ним удаляется снимок
(Range позволяет докачку: снимок удаляется только с последним байтом). Поддержаны
`Range`, `Content-Length`, `ETag` = sha256. Ссылка ведёт на телефон и работает
только из его локальной сети. Не писать её в логи.

Ограничения MCP: агент работает как клиент `agent` (два агента были бы одним
клиентом); токен один на все права; запросы с заголовком `Origin` отклоняются
(403), `GET /mcp` возвращает 405. Не реализованы `deliver` и адресаты,
права на токен, журнал аудита, контур листа, `wait_for_scene_change`.
Проверка: `ANDROID_SERIAL=<device> node scripts/mcp-smoke.mjs`.

### Датчик освещённости (телеметрия)

`GET /status` и MCP-инструмент `status` отдают `sensors.light`: `available`, `name`,
`maxRangeLux` и, когда телефон прислал значение, `lux` (люксы) и `sinceChangeMs`
(сколько миллисекунд назад значение изменилось). Датчик подписан в службе камеры и
**только сообщает значение**: ничто в приложении не меняет настройки камеры по свету.
Свойства датчика Android: он «по изменению» (новое событие только при изменении
освещённости), поэтому `sinceChangeMs` не возраст данных, а время с последнего изменения;
пока событие не пришло, поля `lux` нет. Обычный датчик стоит на передней стороне рядом с
экраном и показывает свет у экрана, а не то, что видит задняя камера; настоящую освещённость
сцены камера отдаёт сама (ISO и выдержка в EXIF снимка, яркость в метриках `take_photo`).

**Redmi 12 (проверено 2026-10-23):** единственный датчик света на телефоне — виртуальный
`camera_light_Sensor` производителя с максимальным значением 5. Система отклоняет подписку
приложения на него (`registered: false`) и с выключенным экраном, и с включённым при открытом
приложении, поэтому `lux` на этом телефоне получить нельзя. Причина отказа не установлена
(вероятно, ограничение производителя); служба повторяет попытку примерно раз в 30 секунд.
На других телефонах с обычным датчиком освещённости поле заполнится само.

### Калибровка из paper-ledger

`GET /status` объявляет `capabilities: ["calibration-v1"]`. Портал открывает
удалённую калибровку через `/calibration/session` и продлевает свою аренду
каждые 3 секунды. Для вкладок используются независимые clientId; число
одновременных клиентов ограничено 16. `active: false` освобождает только
указанную вкладку. Пропавшие аренды истекают через 12 секунд, проверка раз
в 3 секунды. Локальный экран Android удерживает камеру независимо от аренды.

В удалённом режиме работает тот же CalibrationAnalyzer. Ответ
`/calibration/frame` содержит `jpegBase64`, `width`, `height`, `frameId`,
`ageMs`, нормированные `markers` по TL/TR/BR/BL, `reading` с `liftRight`,
`liftBottom`, `errorPercent`, `aligned`, а также `stable`, `message` и
`tolerancePercent`. JPEG повёрнут так же, как координаты распознавания.
Это превью, оригинальные снимки не выпрямляются и не перекодируются.
Кадры старше 1,5 секунды и кадры со старым допуском не выдаются как свежие.
Без аренд и локального экрана служба возвращается в обычный режим;
ожидающие ACK снимки при переключении сохраняются.

Проверка при запущенной службе и закрытом локальном экране калибровки:
`ANDROID_SERIAL=<device> CAMERA_BASE=http://127.0.0.1:18090 node scripts/calibration-remote-smoke.mjs`.
Нужен соответствующий ADB-forward. Тест проверяет свежий согласованный кадр,
две вкладки, смену допуска, сохранение ожидающего снимка, восстановление
съёмки и автоматическое истечение аренды. Фотографии и токен не сохраняются.

У JPEG-ответа есть `X-Focus-Status`, `X-Capture-Ms`, `X-Image-Width`,
`X-Image-Height`. Размеры относятся к пиксельному буферу до применения EXIF.
В сборке v7 фокусировка только по запросу, без непрерывного AF и наведения
перед снимком. `X-Focus-Status`: `locked` или `on-demand`; прежние версии
возвращали `focused`, `recent`, `failed`, `timeout`, `unsupported`.

`GET /focus` — состояние, `POST /focus` — `{action: "focus" | "lock", x: 0.5, y: 0.5}`.
Координаты нормализованы относительно JPEG-превью с учётом его поворота,
не относительно всей области с чёрными полями. `focus` наводит резкость один
раз и удерживает её; `lock` фиксирует текущее положение объектива без поиска.
Обе команды доступны в обычном режиме и калибровке, но не во время экспозиции.
Новая capability `focus-v1`; состояние также включено в `/status` и пакет
калибровки, поэтому постоянный дополнительный polling не требуется.

Состояния: `idle`, `focusing`, `locking`, `locked`, `restoring`, `failed`,
`unsupported`. `manualLock` — доступность управления дистанцией объектива,
`distance` — зафиксированное значение Camera2 (не обязательно физические метры),
`revision`/`instance` предотвращают откат UI старыми ответами;
`afMode` и `scanCount` — диагностика режима и явно запрошенных AF-сканов.
После успешного AF при наличии дистанции включаются AF OFF и сохранённая
дистанция; фиксация подтверждается CaptureResult и остановкой объектива.
При переоткрытии камеры дистанция восстанавливается без AF-скана; съёмка
после смены разрешения ожидает подтверждения восстановления (с таймаутом).
Без ручного управления удерживается CameraX AF-lock до переоткрытия;
после него UI просит навести фокус снова и не обещает сохранение положения.
Настройка хранится только в живой службе: после её перезапуска нужно повторное
наведение. Экспозиция и баланс белого не блокируются.
Текущие экспериментальные значения: свежесть AF 5 с, ожидание AF 1,8 с,
превью около 640×480, отключение камеры после 15 с без обращений.

HTTP-сервер написан на стандартных ServerSocket/Executor; ограничены рабочие
потоки, очередь, размер заголовков/команды, чтение по таймауту. Это небольшой
стенд для локальной сети, не готовый публичный сервер. HTTP не защищает
содержимое и токен от перехвата. Доступ с произвольного origin не включать.

## Ограничения стенда

- QR-привязка, реестр нескольких телефонов и серверная ретрансляция ещё не
  реализованы. Вместо QR используется локальный адрес с кодом доступа.
- Список разрешений берётся из Camera2. Комбинация use cases CameraX может
  выбрать близкий поддерживаемый режим; фактические размеры возвращаются в
  результате. Не обещать точное соответствие всем advertised размерам до
  отдельной проверки combinations.
- Код помнит до 256 завершённых запросов текущего процесса. Производственный
  протокол должен валидировать сессию/порядок команд, чтобы не допустить
  повторную съёмку после вытеснения старого идентификатора.
- Пульт повторяет запрос с прежним ID после сетевой ошибки, но не восстанавливает
  его после перезагрузки страницы. `pagehide`-отмена — best effort, не гарантия
  обнаружения закрытой вкладки; bfcache и закрытие процесса требуют дальнейшей
  проработки.
- Файлы хранятся в приватном files/captures до ACK/замены/отмены, при старте
  службы незавершённые файлы удаляются. В системную галерею снимки не попадают.
- Запуск foreground service выполняется пользователем из видимой Activity.
  Без подписчиков камера освобождается, служба остаётся; повторное открытие и
  долговременную живучесть нужно проверить на целевом Redmi.
- Включение постоянной подсветки реализовано; вспышка только на снимке ещё нет.
- Настройка имени, отзыв доступа, стабильный ID камеры и сохранение выбранной
  камеры относятся к следующей стадии интеграции.

## Дальнейшая интеграция

Обновление 2026-10-20: в рабочей копии paper-ledger реализованы `/camera`,
встроенный пульт на `/`, общий метод `PaperLedgerPages.add` и same-origin
серверный шлюз к существующему HTTP-серверу телефона. Реальное превью и JPEG
4080×3060 проверены в Chrome. Обновление APK для этого пути не требуется.
Подробности и ограничения сети — `paper-ledger/docs/CAMERA.md`.
Публичный сервер ещё не обновлялся.

Пикер и камера теперь используют общий метод добавления `File`; endpoint
обработки документа не используется как приёмник одиночного снимка. Остаётся
выбрать транспорт для рабочей сети с удалённым домашним сервером. Любой новый
relay должен сохранять адресацию вкладки и ждать именно ACK браузера.
