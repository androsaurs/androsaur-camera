# androsaur-camera: телефон, который снимает по команде

Обычный Android-телефон на штативе, который превращается в документ-камеру: вы смотрите
на лист в браузере компьютера, нажимаете кнопку и получаете оригинальный снимок в 12,5
мегапикселей. Без облака, без пересжатия в мессенджере, без возни с телефоном в руках.
А ещё эту же камеру можно отдать ИИ-агенту, и он научится снимать, проверять и пересъёмывать
страницы сам. Проект родился как документ-камера для paper-ledger, который разбирает бумажные
накладные, и вырос из этой задачи.

## Как это выглядит

Телефон стоит на штативе над столом. Приложение, которое работает в фоне, даже когда экран
выключен, поднимает на телефоне небольшой сервер. Вы открываете его страницу на компьютере в
той же сети и видите живое превью. Положили лист, нажали «снять» и меньше чем через секунду получили
исходный JPEG прямо в браузере. Телефон при этом файл не хранит: как только браузер подтвердил
получение, копия на телефоне удаляется.

Скорость на Redmi 12: при хорошем свете снимок 4080×3060 готов за **0,46 секунды** по USB и
**0,55 секунды** по Wi-Fi, в тёмной комнате за 0,75 и 0,99 секунды. Шестьдесят снимков подряд
идут ровно, без замедления, а телефон прогревается меньше чем на градус. Для потока документов это с большим запасом.

## Что в нём приятного

**Оригинал остаётся оригиналом.** Снимок отдаётся ровно таким, каким его отдала камера: без
ресайза, без выравнивания, без повторного сжатия. Всё, что нужно сделать с кадром (выровнять
лист, распознать текст), делает тот, кто его получил.

**Штатив ставится по подсказке.** Режим калибровки ищет на столе четыре одинаковых QR-кода и
говорит, какой край телефона приподнять, чтобы камера смотрела на лист строго сверху. Когда всё
ровно, рамка зеленеет. Калибровку можно запускать и из браузера, не подходя к телефону.

**Фокус как вы скажете.** Нажали на нужную точку, камера навелась и держит резкость до следующей
команды. Никакого «охотящегося» автофокуса, который сбивается перед самым снимком.

**Превью, которое не тормозит.** Живой кадр отдаётся от 17 до 30 раз в секунду в зависимости от
света. Смотреть можно с нескольких вкладок сразу (проверено с шестью): все видят один и тот же
кадр и друг друга не замедляют.

## Свет решает всё

Самое неожиданное, что мы узнали про скорость: она почти целиком зависит от освещения. В
тёмной комнате автоэкспозиция берёт длинную выдержку, и камера физически не может отдавать
больше 17 кадров в секунду. При свете превью оживает до 30. Можно заставить камеру держать 30
кадров и в темноте, но тогда снимки получаются в два с половиной раза темнее и мягче, и для
документов это плохая сделка. Поэтому приложение оставляет автоэкспозицию, а
самое действенное ускорение по нашим замерам это хороший свет над столом.

## Камера для ИИ-агента

Внутрь приложения встроен сервер MCP, то есть набор инструментов, которыми агент (например,
Claude Code) управляет камерой напрямую: посмотреть превью, снять, включить подсветку,
навести фокус. Агенту не нужно «видеть» каждую страницу, чтобы понять, годится ли она:

1. `take_photo` возвращает не картинку, а хэндл снимка; **цифры** (резкость, яркость, контраст, доля
   пересвета) агент запрашивает, когда они нужны: пока не попросили, телефон ничего не считает.
2. Если есть сомнение, агент просит **уменьшенный вид** страницы или **лупу**: вырез из
   оригинала в родном разрешении, чтобы прочитать мелкий текст.
3. Когда страница хороша, агент берёт одноразовую **ссылку** и передаёт её дальше обработчику
   как обычный текст. Сами байты не проходят через модель, то есть токены на картинку не тратятся.

Так страницы документа можно снять, проверить и передать дальше, ни разу не показав агенту
картинку целиком.

## Глаза ассистента Androsaur

В голосовом ассистенте [Androsaur](https://github.com/androsaurs) эта же камера смотрит на людей. Сканер никуда не делся, но здесь
по умолчанию включена фронтальная камера (`POST /camera {lens}` или MCP `set_camera` переключают на заднюю).

**Слежение за лицом** (`GET|POST /faces`, MCP `face_lab`): несколько детекторов на одних кадрах — чип камеры, ML Kit, MediaPipe
BlazeFace (по умолчанию, около 20 кадров в секунду) и Face Landmarker (478 точек и поза головы). Наружу уходят только числа: рамка лица
как доли кадра, наклон, оценка. Картинку агент получает, только если сам попросит.

**Люди.** Человека учат на экране «Люди» прямо на телефоне: до 12 снимков при разных положениях головы. Из каждого снимка получается
набор из 128 чисел (SFace int8), и только эти наборы хранятся, фотографии — никогда. Узнавание сравнивает лицо в кадре с наборами
(среднее трёх лучших совпадений, порог 0,55, настраивается на экране).
- У каждого человека **постоянный ID**: переименование меняет только имя, поэтому всё, что другие приложения связали с человеком
  (например, голосовые записки ему), остаётся за ним.
- `GET /people` — люди (ID, имя, число наборов, отпечаток наборов), модель лиц и `who`: кто перед камерой (ID и имя);
  `POST /people/identify {ms}` включает узнавание на короткое окно; `POST /people/rename {id|name, to}`, `POST /people/forget {id|name}`.
  MCP: `people`, `identify`, `rename_person`, `forget_person`.
- **Для домашнего хаба** (только приложениям с той же подписью): `GET /people/export` отдаёт людей с наборами,
  `POST /people/import` принимает людей дома (новые добавляются, у знакомых добавляются недостающие наборы, до 60 на человека),
  `POST /people/merge {from, into, name}` объединяет человека, обученного здесь, с человеком дома. Так новый телефон узнаёт семью без
  обучения, а люди с телефона из другой системы сливаются с людьми дома.

## Честно о приватности

Снимки документов и лица людей — личные данные, поэтому приложение хранит их как можно
меньше: лица — только как наборы чисел, без фотографий; снимки — в приватной папке телефона, а не в галерее. Снимок для браузера удаляется, как только
браузер подтвердил получение. Снимок для агента удаляется сразу после доставки по одноразовой
ссылке, а невостребованный исчезает через минуту. Доступ закрыт кодом доступа, облачных
сервисов приложение не использует. Но есть и честное ограничение: связь по HTTP без шифрования,
поэтому камера рассчитана на доверенную локальную сеть.

## Чего ещё нет

- привязки телефона по QR-коду и работы через сервер, когда телефон и компьютер в разных сетях;
- установки без ручного APK и без подтверждения на телефоне;
- датчика освещённости: на Redmi 12 система не даёт приложению подписаться на него,
  поэтому свет сцены можно судить только по самой камере;
- проверок на других телефонах: всё измерено на Xiaomi Redmi 12 с Android 15.

## Куда дальше

Идея переросла стол с бумагами: камера, которая снимает по команде, пригодится и ИИ-агентам, и,
возможно, роботу. Наброски такой универсальной камеры, не ломающей исходную задачу, лежат в
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Попробовать

```sh
./gradlew :androidApp:assembleDebug
adb install -r androidApp/build/outputs/apk/debug/androidApp-debug.apk
```

Откройте приложение, разрешите камеру и откройте на компьютере адрес пульта с экрана телефона
(адрес содержит код доступа, не публикуйте его). Подключить агента:

```sh
claude mcp add --transport http androsaur-camera http://<адрес телефона>:8088/mcp \
  --header "Authorization: Bearer <код с телефона>"
```
